# Fixed widget port status

**Snapshot:** 29 September 2026. This describes the standalone `operator-display-client` Fixed workbench and viewer, not the full Appsmith editor. “Exposed” means a type can be added from the local palette and has a local render and property configuration path. It does **not** mean every Appsmith event, binding, editor control, or external service works.

## Catalog reconciliation

The current Appsmith Fixed palette includes Card. Appsmith [registers `CARD_WIDGET`](app/client/src/widgets/index.ts), its [configuration](app/client/src/widgets/CardWidget/widget/index.tsx) has a Display tag and visible card, and the [sidebar selector](app/client/src/selectors/editorSelectors.tsx) includes registered non-WDS widgets in Fixed layout unless their cards are hidden. The checked-in [sidebar test fixture](app/client/src/pages/Editor/widgetSidebar/tests/UIEntitySidebar.fixture.ts) is a 2024 snapshot with 46 widget types and eight `BUILDING_BLOCK` templates; Card was added to Appsmith in 2026, after that fixture was last updated. The [local Fixed palette](operator-display-client/src/features/workbench/WorkbenchPage.tsx) exposes the 47 current types. Appsmith's [Custom `getConfig()`](app/client/src/widgets/CustomWidget/widget/index.tsx) hides its card in airgapped mode; the local palette currently exposes Custom without that environment check.

The [local property registry](operator-display-client/src/editor-bridge/property-controls/config/index.ts), addable type/default map, and [shared canvas renderer](operator-display-client/src/editor-bridge/read-only/NativeReadOnlyCanvas.tsx) cover these 47 types. The renderer also recognizes some older saved types, such as legacy Table and Progress, which are **not** additional palette entries. The matrix below names all 47 exposed types exactly once. Card needs its own canvas and header/media/menu/footer zones in Appsmith, so its local renderer and blueprint have more structure than a simple display widget.

## Cross-cutting limits

- **Bindings:** The saved static resolver accepts only restricted `{{WidgetName.propertyPath}}` references; it does not evaluate arbitrary Appsmith JavaScript. The guided Cyflex binding editor and [`displayTargets`](operator-display-client/src/editor-bridge/live-bindings/displayTargets.ts) support only Text `text` and Chart `chartData.<series>.data`. Rendering 47 widget types does not make all 47 live data targets. Unknown or unsupported dynamic values remain unresolved in the viewer.
- **Events and actions:** [Document validation](operator-display-client/src/document/validation.ts) rejects configured `on...` handlers and nonempty `dynamicTriggerPathList`. Browser controls may update transient widget meta or expose a callback, but they do not execute Appsmith `executeAction`, queries, navigation, uploads or arbitrary JS. Default Form/Modal buttons and Card actions are visual surfaces without those behaviors. Transient values are separate from authored defaults and are not saved as dashboard content.
- **Editor:** The property registry covers all 47 types using a bounded set of static controls. It lacks Appsmith's general JS/code editor, action selector, full JSON Form field editor, menu item editors and several specialized one-click binding controls. The Custom source popup is a dedicated editor for that widget; it is not the general Appsmith property editor.
- **Services:** The Java-shaped marketplace/dashboard API and local IndexedDB draft paths are separate from widget presentation. The local browser checks use fixture or intercepted Java responses. [Run dashboard](operator-display-client/src/features/workbench/WorkbenchRunPanel.tsx) requires deployment injection of `window.operatorDisplayRunEnvironment.connectionForCell`, browser NATS options and a verified timestamp conversion; the mock Java server does not provide a live broker. No live Java/NATS session, publish flow, Google Maps key, cloud picker, external Office fetch or physical capture device was established by this audit.

## Verification boundary

On this snapshot, `tsc --noEmit`, `scripts/check-boundary.cjs`, and the production Vite build passed. All **26** checked-in native widget `*.contract.test.cjs` files and **11** focused native widget `*.browser.test.cjs` files passed against local Vite and headless Chrome. Separate Custom builder and popup-bridge browser harnesses passed as well. The strengthened `scripts/verify-all-fixed-widgets.cjs` confirms all 47 palette types can be added, rendered, persisted and reloaded; it selects Modal from the outline after reload because Appsmith hides an unselected Modal. The full `scripts/verify-browser.cjs` workbench regression also passed. These checks establish local render/interaction slices and document persistence, not full Appsmith feature parity or a live backend.

The older [Fixed widget content roadmap](FIXED_WIDGET_CONTENT_ROADMAP.md) and several module notes describe earlier integration stages. The palette, renderer, property registry and current tests cited above are the source for this snapshot's exposure and wiring claims.
