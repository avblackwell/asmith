# Fixed widget content roadmap

> Historical planning inventory. The palette and renderer now expose 47 current Appsmith Fixed widgets. The 2024 sidebar test fixture predates Card's 2026 registration, so its 46-widget count is stale. See [Fixed widget port status](FIXED_WIDGET_PORT_STATUS.md) for current coverage, verification and open behavior gaps. The “present product contract” and “practical order” below describe the earlier stage of the port.

Source review: 2026-09-29. Scope is the checked-in Community Edition client and the extracted Fixed-layout workbench. This is an implementation inventory, not a promise that every registered widget belongs in the product palette. Appsmith registers 90 literal type keys plus the symbolic `SECTION_WIDGET` and `ZONE_WIDGET` keys in [`app/client/src/widgets/index.ts`](app/client/src/widgets/index.ts), mixing legacy, WDS, migration, and internal types. The CE extension arrays are empty in [`ee/widgets/index.ts`](app/client/src/ee/widgets/index.ts) and [`ee/widgets/wds/index.ts`](app/client/src/ee/widgets/wds/index.ts). A loader's presence alone does not establish its Fixed-layout availability or a usable product runtime.

## Present product contract

The workbench palette and add command expose **Text, Chart, Container, Image, Divider, Progress, Tabs, Modal, List V2, and Stats Box** (`TEXT_WIDGET`, `CHART_WIDGET`, `CONTAINER_WIDGET`, `IMAGE_WIDGET`, `DIVIDER_WIDGET`, `PROGRESS_WIDGET`, `TABS_WIDGET`, `MODAL_WIDGET`, `LIST_WIDGET_V2`, `STATBOX_WIDGET`; [`WorkbenchPage.tsx`](operator-display-client/src/features/workbench/WorkbenchPage.tsx), [`editDocument.ts`](operator-display-client/src/editor-bridge/editable-store/editDocument.ts)). These ten have property-pane metadata in [`property-controls/config/index.ts`](operator-display-client/src/editor-bridge/property-controls/config/index.ts). The Fixed renderer also recognizes structural `CANVAS_WIDGET` and paints `BUTTON_WIDGET` and `ICON_BUTTON_WIDGET` as static children of the Modal or Stats Box blueprint; those action widgets do not yet have a standalone product contract ([`NativeReadOnlyCanvas.tsx`](operator-display-client/src/editor-bridge/read-only/NativeReadOnlyCanvas.tsx)). List V2 has an editable literal `listData` property, local pagination, and runtime-only rows; its template cannot yet be edited because Appsmith's meta-widget editor is not mounted ([`native-widgets/list-v2`](operator-display-client/src/editor-bridge/native-widgets/list-v2/README.md)).

The compatibility Redux tree has **empty meta widgets and loading state**, and resolves only selected safe static widget references ([`compat-store/index.ts`](operator-display-client/src/editor-bridge/compat-store/index.ts), [`resolveStaticReferences.ts`](operator-display-client/src/editor-bridge/static-bindings/resolveStaticReferences.ts)). Cyflex live display targets are Text `text` and Chart series data ([`displayTargets.ts`](operator-display-client/src/editor-bridge/live-bindings/displayTargets.ts)). Dashboard validation rejects configured Appsmith `onX` handlers and nonempty `dynamicTriggerPathList`, even on imported DSL ([`validation.ts`](operator-display-client/src/document/validation.ts)). These limits matter when a widget's Appsmith `getWidgetView()` looks simple but its behavior depends on evaluated properties, meta state, or `executeAction`.

## Registered legacy widgets by runtime requirement

Types below come from the legacy section of [`widgets/index.ts`](app/client/src/widgets/index.ts). A type can have a useful visual-only slice without its full Appsmith behavior; that distinction is explicit. The implemented List V2 and Stats Box entries remain in the canvas-owning table to show their remaining runtime limits; other supported types are named above and omitted below.

## WDS registry boundary

The same loader registry also lists WDS presentation (`WDS_PARAGRAPH_WIDGET`, `WDS_HEADING_WIDGET`, `WDS_STATS_WIDGET`, `WDS_KEY_VALUE_WIDGET`), WDS input/action (`WDS_BUTTON_WIDGET`, `WDS_INPUT_WIDGET`, `WDS_CHECKBOX_WIDGET`, `WDS_ICON_BUTTON_WIDGET`, `WDS_CURRENCY_INPUT_WIDGET`, `WDS_TOOLBAR_BUTTONS_WIDGET`, `WDS_PHONE_INPUT_WIDGET`, `WDS_CHECKBOX_GROUP_WIDGET`, `WDS_COMBO_BOX_WIDGET`, `WDS_SWITCH_WIDGET`, `WDS_SWITCH_GROUP_WIDGET`, `WDS_RADIO_GROUP_WIDGET`, `WDS_MENU_BUTTON_WIDGET`, `WDS_INLINE_BUTTONS_WIDGET`, `WDS_EMAIL_INPUT_WIDGET`, `WDS_PASSWORD_INPUT_WIDGET`, `WDS_NUMBER_INPUT_WIDGET`, `WDS_MULTILINE_INPUT_WIDGET`, `WDS_SELECT_WIDGET`, `WDS_DATEPICKER_WIDGET`, `WDS_MULTI_SELECT_WIDGET`), WDS complex widgets (`WDS_TABLE_WIDGET`, `WDS_MODAL_WIDGET`, `WDS_CUSTOM_WIDGET`), and Anvil structure (`SECTION_WIDGET`, `ZONE_WIDGET`). Source: [`widgets/index.ts`](app/client/src/widgets/index.ts), [`wds/constants.ts`](app/client/src/widgets/wds/constants.ts), and a representative [`WDSParagraphWidget/config`](app/client/src/widgets/wds/WDSParagraphWidget/config/index.ts). ## Practical order after Tabs, Modal, static List, and Stats Box

1. **Define Modal's actions.** The Appsmith-style detached four-edge resizer is now integrated with pixel limits, Auto Height's vertical gate, child-canvas bounds, undo, save, and browser checks. The default Close and Confirm children still need a product action contract before they can be interactive. See the [Modal source map](operator-display-client/src/editor-bridge/native-widgets/modal/MODAL_AUTOHEIGHT.md).
2. **Add import compatibility for retired display widgets; choose any new media display surfaces by product need.** ProgressBar and Circular Progress can map to the existing Progress renderer. Document Viewer is the cleanest new literal display widget. Video/Audio need an explicit decision on media events and playback state before being called complete.
3. **Define the product widget-state and action contracts, then port one input family.** Use Appsmith's control/component/config files, but route changes through a product Redux state slice and its saga boundary. A Button without a safe action schema or a Select without selected-value meta would be a misleading palette item. Table, JSON Form, dynamic List, maps, and custom/iframe widgets follow only when the evaluator, action, or external-runtime contracts they need exist.

For each new type, review the source widget's `getConfig`, defaults/blueprint, component, property-pane config, meta/default/derived-property maps, and `getWidgetView`; then add an isolated source map, pure blueprint/validation tests, renderer tests, and one edit/view/undo/reload browser path. The product's stored DSL should contain authored widgets only; selection, page state, generated rows, media state, and event results belong in transient runtime state.
