Snapshot: 2026-09-29. This compares the checked-in Appsmith client in app/client/src with the independent operator-display-client workbench. It covers Fixed layout and the locally supported widgets. Appsmith's Redux actions are mapped to the product's Redux/saga document commands; the product does not call Appsmith's backend.

## Current behavior

| Area | Result | Boundary |
| --- | --- | --- |
| Per-canvas arena | Each mounted Fixed CANVAS_WIDGET gets its own slider, sticky paint canvas, pointer enter/move/leave/release listeners, and cached preview. Nested Container, Statbox, Tabs, and Modal canvases own their targets. Drag-time widget stacking follows Appsmith's positioned widget z-index rule, allowing the nested slider to receive events above the root arena. | The complete Appsmith editor shell and all widget types are not mounted. |
| Drop preview | The arena draws snapped blocks on its own Canvas2D surface. A backing-canvas rescale repaints the cached preview. The dotted grid remains a separate drop-target layer. Delayed 500 ms Container reflow updates the active plan, repaints without pointer movement, and is the plan committed on release. | A paired authenticated Appsmith recording is still needed for transition timing and exact paint comparison. |
| Edge geometry | Palette and existing-widget movement call Appsmith's modifyBlockDimension rule. The resulting columns/rows or right/bottom coordinates travel through the preview and Redux/saga commit, so saved geometry matches the last valid block rather than a default size with a clamped origin. Auto-height blocks keep source fixedHeight semantics at vertical edges. Existing widgets use Appsmith's bounded fractional grid-cell grab point and re-snap it for each destination canvas. | The supported palette is a subset of Appsmith's widgets. |
| Scroll and exit | Scroll replay uses the slider's adjusted offsetY, and leaving a canvas clears its preview. The arena stays mounted until the global drag ends, matching Appsmith's showCanvas lifecycle. The release path uses the newest accepted plan, including delayed reflow. | Extremely short synthetic drags are still subject to arena mounting timing; see below. |
| Live resize and chrome | The widget name is a sibling of React Spring's ResizeWrapper inside the positioned widget. The rendered content and eight handles are children of that same animated wrapper; its border, shadow, and outline follow Appsmith's source. Hover enables handles, auto-height keeps top/bottom handles in the DOM with inactive dots, and the name hides during drag or resize. The actual widget changes size and translation before Redux persists the edit. Rejected pointer samples retain the last accepted rectangle per axis, including the 2-column and 4-row minimums, and release commits that rectangle. Hidden-widget opacity applies to the source-shaped VisibilityContainer inside the resize wrapper, leaving chrome clear; resize-disabled widgets bypass both wrappers. | The pointer and keyboard handlers still adapt to the product's Redux/saga document commands. A paired Appsmith editor recording is needed for pixel and gesture timing comparison. |
| Nested height | The canvas grows temporarily during drag/resize. A Fixed resize persists the parent canvas bottomRow in pixels, including Appsmith's +2 nested or +8 root extension rows. Auto-height recalculation preserves that pixel value. Nested canvases render in normal flow with explicit row height, as Appsmith's DropTargetComponent does, so an empty Auto Height Container has a real drop surface. | Imported DSL and uncommon canvas-owning widgets need separate comparison. |

The implementation also retains Appsmith's 64-column grid, 10 px rows, prior reflow maps, 500 ms Container gate, and the product's undoable document command. The local planner still validates its own saved DSL and can try another reflow direction when a bounded target has no room; this is a remaining behavioral difference from a single Appsmith drag sample.

## One-step palette jump

A Chrome trace of a synthetic one-step move into the root canvas showed the pointer arrive before Redux mounted the drag slider. The browser delivered mouseover to the new slider before its effect attached the listener; without another mousemove, there was no preview or drop. A later run did produce a valid one-step preview, so this is timing-sensitive. A normal multi-step drag and one-step drops into already mounted nested canvases have passed.

Appsmith's WidgetCard starts from native dragstart, its FixedCanvasDraggingArena mounts conditionally, and useCanvasDragging installs listeners in an effect. The checked-in Cypress drag helper sends two mousemoves to the target before mouseup. This source supports the same timing possibility but does not prove an Appsmith browser result. The local Appsmith instance at 127.0.0.1:8080 redirects to a login page and the development client at 3001 did not serve an editor, so the paired browser fixture could not be run. No mount-time cursor hit test or global event fallback was introduced because those would add a gesture path absent from the inspected source.
