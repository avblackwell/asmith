The [administration wiki](C:/Users/alexb/Downloads/backend/markerplace_backend/wiki/administration.md:3) describes intended Users, Groups, Permissions, Test Cell Setup, and Universal Variables screens; the registered [Java resource tree](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/api/WebResource.java:74) determines what can work now. ## Identity, authorization, and data shape

- A session supplies an Entra username; the Java app resolves an **existing** `user_info` row by username. This source does not auto-create users or import Entra group claims on login. [SessionService](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/services/SessionService.java:17), [UserService](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/services/UserService.java:75)
- `GET /system/userInfo` returns `id`, `username`, `isSystemAdmin`, and `groupMemberships`. The numeric `id` is the database-generated `user_info.id`. [User DTO](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/data/User.java:9), [schema](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/resources/sql/init.postgres.sql:383)
- System-admin status comes from **membership** in the specially named `System Administrators` group, regardless of that member's `ADMIN` or `MEMBER` group role. A group `ADMIN` can manage that group; a system admin can manage all groups. [System-admin query](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/resources/com/trplabs/cyflex/operator_display/dao/is-user-system-admin.sql:1), [group permission](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/dao/UserGroupDao.java:876)
- `groupId` is an internal `user_group.id`; member-add `userId` is an internal `user_info.id`; `externalGroupId` is a **string** intended for a Microsoft Entra group ID. [Group/member requests](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/data/group/UserGroupCreateRequest.java:5), [membership FK](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/resources/sql/init.postgres.sql:374)
- Lists use `search`, numeric offset `cursor`, `limit` (default 20, maximum 100), paired repeated `sort`/`sortValue`, and `filter`/`filterValue`. Responses are `{data,meta}`. Sorting in these screens must be server-driven; a table control sorting only loaded rows would misrepresent a paginated list. [Request](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/data/query/PaginatedQueryParams.java:17), [response metadata](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/data/query/PaginatedQueryMetadata.java:27), [pagination defaults](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/dao/PaginationDao.java:615)

## Backend issues to resolve before presenting complete admin workflows

1. **Visibility filters are not reliable authorization predicates.** The shared paginator joins all filters with `OR`. Site/test-cell list services insert the user visibility filter into that same set, so another valid caller filter can widen results. The group-list forced filter also composes incorrectly with optional filters; its `created_by_user` predicate may additionally fail in PostgreSQL because it references a SELECT alias. Fix filtering in Java/SQL, and enforce access in the list query independently of user-supplied facets. Hiding filters in the UI does not fix the endpoint. [Paginator](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/dao/PaginationDao.java:502), [site filter](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/services/SiteService.java:103), [test-cell filter](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/services/TestCellService.java:55), [group filter](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/services/GroupService.java:100)
2. **User lifecycle is incomplete.** Fix the absent-user lookup and JDBC generated-key handling in create; implement deletion policy or leave deletion absent. There is no profile edit or invitation API. [Create service](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/services/UserService.java:145), [DAO](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/dao/UserDao.java:111), [delete stub](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/api/system/UserResource.java:54)
3. **Group deletion and reserved-group rules need repair.** Delete dependent assignment rows before their parent in a transaction; decide whether system groups may ever be edited/deleted. Add explicit protection for the last system administrator; group `ADMIN` count is not the same as system-admin count. [DAO order](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/java/com/trplabs/cyflex/operator_display/dao/UserGroupDao.java:314), [system-admin query](C:/Users/alexb/Downloads/backend/markerplace_backend/src/main/resources/com/trplabs/cyflex/operator_display/dao/is-user-system-admin.sql:1)
