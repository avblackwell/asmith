# Canvas parity audit

Source review: 2026-09-28. This compares the checked-in Appsmith client under `app/client/src` with the extracted workbench under `operator-display-client/src`. It covers the canvas, the widgets it renders, and the editing controls immediately around it. The baseline tables below remain the original source audit; the implementation status above them supersedes their old product column.

The current drag, edge geometry, live resize, and remaining comparison work are tracked in [FIXED_DRAG_PARITY_REVIEW.md](FIXED_DRAG_PARITY_REVIEW.md). Its 2026-09-29 status supersedes the earlier Fixed drag notes in this audit.

## Fixed-layout implementation update

The comparison tables below record the **baseline before implementation**. The extracted client now has these Appsmith Fixed layout slices:

- Appsmith's pure fixed-layout reflow core is copied under `operator-display-client/src/editor-bridge/editable-store/appsmith-reflow/`, with the source and local adaptations documented in its README. `fixedLayoutPlanner.ts` runs that core for an occupied-space edit and rejects results that exceed the canvas or overlap.
- `appsmith-fixed-drag/reflow-session/` now carries Appsmith's previous positions, collision, movement, and second-order collision maps across pointer samples on one canvas. The pointer preview passes its final displacement map through the same bounds checks used by a new atomic Redux/saga commit command. The editor resets that history when the drag ends or changes canvases. Appsmith's stationary 500 ms Container reflow retry is part of the session.
- `editDocument.ts` uses the same planner for add, move, resize, and `previewLayoutChange`. A committed command applies displaced siblings in the same undoable document update. Moving between root and nested Container canvases updates parent/child links; resizing from a north or west handle updates the widget origin.
- `EditableCanvas.tsx` now uses Appsmith's fixed-layout visual vocabulary: the dotted active-canvas grid and Canvas2D blue/red placement blocks from `DragLayerComponent` and `useRenderBlocksOnCanvas`; the right-aligned orange widget-name badge, selection border, and eight resize hit areas from Appsmith's widget-name and resizer styles. The source mapping and local adaptations live in `editor-bridge/appsmith-fixed-drag/README.md`.
- The widget palette and existing widgets use an Appsmith-style shared Redux drag session with Appsmith-derived per-canvas Fixed drag arenas. The palette places a new widget from Appsmith's top-right cursor anchor and uses its edge dimension rule. An existing dragged widget becomes hidden during the preview, while the actual displaced sibling elements animate to their proposed positions. Both paths use the same fixed-layout planner and Redux/saga document commands. Keyboard add and move/resize remain available.
- The ten supported palette widgets, including Tabs, Modal, List V2, and Stats Box, display Appsmith's SVG thumbnails at the source widget-card size, with its hover treatment.
- `appsmith-fixed-drag/container-hover` ports the source's 500 ms stationary-cell gate for reflow of a colliding Container, Stats Box, Tabs, or detached Modal. Nested canvas activation itself remains immediate, as in `useCanvasDragging` and `useReflow`.
- `appsmith-fixed-geometry` and `appsmith-fixed-autoheight/autoHeightRules.ts` derive root render height from the hydrated child layout, 64-column snapped widths, 10 px rows, and Appsmith's 6 px child placement offset. The root uses `(width - 12) / 64`; an ordinary nested canvas uses `(width - 20) / 64` and keeps 64 logical columns when its Container is added or resized. `NativeReadOnlyCanvas`, `EditableCanvas`, `editDocument`, and the group commands use these rules. Saved root `bottomRow` is normalized to content pixels after layout edits while `minHeight` remains separate.
- `appsmith-fixed-selection` ports the Fixed Canvas2D marquee, visible-area backing canvas, modifier and Shift range selection, shared blue dashed group box, action rail, and multi-widget property pane. Its marquee now clips through the actual nested canvas's scroll ancestors and tracks selection during edge scrolling. The workbench dispatches copy, cut, paste, delete, group, and group move through local Redux actions and sagas. Group operations commit one undoable document update. Copy/cut use an account- and deployment-scoped IndexedDB clipboard, including referenced Cyflex variables; paste follows Appsmith's selected-widget, Container, and next-row target rules across Fixed drafts.
- Ordinary invisible widgets remain dimmed on the editing canvas and collapse in viewer mode, following `withWidgetProps` and Appsmith's `invisible` style.
- Fixed auto height is connected for Text, Container, Stats Box, Tabs, and detached Modal within their supported contracts. New widgets and grouped Containers receive Appsmith feature defaults; legacy widgets without a height mode stay Fixed. Text content is measured through `ResizeObserver`, with mode and limit controls in the property pane and the selected-widget pink limit overlay. The editor store uses Appsmith's copied dependency-tree/reflow functions to move siblings and propagate nested Container/Stats Box heights. Tabs selects one child canvas for transient height projection. Modal updates its pixel panel height without moving root siblings. Measurements do not add undo entries; explicit auto-height containers are checked on editor mount. Source maps are in `operator-display-client/src/editor-bridge/appsmith-fixed-autoheight/README.md` and the native Tabs/Modal/Stats Box packages.
- Fixed canvas width choices now use Appsmith's `MainContainerWidthToggles` ADS segmented control, the same Fluid/Desktop/Tablet/Mobile labels and ranges, and its `resolveCanvasWidth` rule. The chosen preset is undoable document compatibility data; the resolved pixel width is transient Redux canvas state. ## Why the canvas feels smaller

The dashboard JSON is **not** the cause. Appsmith also renders a widget DSL with `CANVAS_WIDGET` children. The difference is what consumes that DSL. Appsmith's `CanvasFactory.tsx:12-50` selects an edit or view canvas for the active layout system and hydrates widget properties. Its fixed editor canvas assembles drop targets, a drag arena, a selection arena, a multi-selection layer, and wrapped widget children (`layoutSystems/fixedlayout/canvas/FixedLayoutEditorCanvas.tsx:21-25,96-129`). Each fixed-layout widget receives editor wrappers for focus, dragging, name and error display, resizing, auto height, and tab order (`layoutSystems/fixedlayout/editor/FixedLayoutEditorWidgetOnion.tsx:15-29,60-93`).

At the audit baseline, the extracted workbench mounted `EditableCanvas` around `NativeReadOnlyCanvas`, with custom selection and drag feedback. The fixed-layout changes above now reuse Appsmith's grid, Canvas2D preview, widget chrome, and reflow geometry through a small local adapter. `NativeReadOnlyCanvas` still renders only the product's supported widget types. The local Redux and sagas implement product document commands, rather than Appsmith's full editor action graph.

## What is already present

The product canvas is editable within a defined subset: six palette widgets; placement on the root or nested Container canvas; single-widget selection; grid-snapped pointer and arrow-key move/resize; property edits; delete; local undo/redo; draft save; static widget references in selected display properties; and a transient Cyflex display overlay. See `WorkbenchPage.tsx:64-92,488-527,580-597,712-763`, `EditableCanvas.tsx:112-143,223-329`, `editDocument.ts:330-382,461-540`, and `editable-store/index.ts:118-169`. These should not be described as wholly absent.

## Suggested order for closing the gap

1. **Make the fixed canvas correct.** Port or adapt Appsmith's occupied-space, drag preview, collision/reflow, drop-target, and resize logic while preserving the product's Redux/saga command boundary. Add source-parity interaction fixtures for placement, overlap, cross-container movement, nested scroll, and all resize edges.
2. **Restore editor selection and chrome.** Multi selection, marquee, group/clipboard operations, hidden-widget editing, per-widget name/error/focus layers, and keyboard shortcuts. These are frontend tasks.
3. **Expand rendering and evaluation deliberately.** Port widgets in useful groups with their real widget contracts; add the evaluator/meta-state capabilities each group requires. Preserve the dashboard document's explicit safe binding and action policy until product behavior is defined.
4. **Add Auto/Anvil only if dashboards need them.** They are distinct layout models with different DSL and editing algorithms, not a CSS switch on the Fixed canvas. Backend deployment is not required to implement or test their frontend interactions, but document/schema support is.

The existing Appsmith client contains the relevant components and algorithms. Their imports also reach much of Appsmith's global store, sagas, evaluator, and API code, so a direct file copy is not sufficient to keep the extracted client independent. The gap can be closed incrementally around the product-owned document and command contracts; it is not a JSON serialization problem.

For scale, I reran `node scripts/audit-native-graph.cjs pages/Editor/Canvas.tsx` from `operator-display-client`. The static import graph reaches 1,243 Appsmith source files, including 190 layout-system files, 126 saga files, 95 reducer files, and 63 API modules. Those are **import reachability counts**, not requests made when the canvas opens. They explain why mounting Appsmith's full `Canvas` entry in this bundle currently pulls in backend-facing code.

## Verification and limits

This audit inspected source paths and traced call sites. `operator-display-client` TypeScript checking passed with `node_modules/.bin/tsc.cmd --noEmit -p tsconfig.json`. It did not run a side-by-side browser session, and it does not claim every Appsmith feature should be exposed in the product. In particular, the inspected source did **not** establish a user-facing canvas zoom control, right-click canvas context menu, or widget lock toggle, so none is counted as a missing feature. The current workbench has working local undo/redo and nested palette drops; both are included in the existing-capability section above.
